# v0.2.0-rc1 Manual Install Load Smoke Procedure

Date: 2026-07-25

## Purpose

Use this procedure to manually prove that the published GitHub prerelease asset for `sap-codex-deliverables-v0.2.0-rc1` can be downloaded, verified, installed into a fresh Codex plugin context, loaded by a new Codex task, and used to produce advisory SAP deliverable output.

This is an app-level smoke procedure. It complements archive extraction tests, but it does not replace release owner, legal, security, SAP tenant, marketplace, or production-readiness approvals.

| Field | Value |
|---|---|
| Release | `sap-codex-deliverables-v0.2.0-rc1` |

| Expected archive size | `1,576,400 bytes` |
| Expected advisory status | Prerelease / release candidate |

## Preconditions

- Use a Codex desktop app session that can install local plugin bundles.
- Use a fresh Codex task for the app-level smoke. Do not reuse the release engineering task.
- Keep the smoke disconnected from live SAP tenants.
- Do not enable MCP servers, hooks, tenant credentials, production actions, or transport automation.
- Do not add client data, credentials, personal data, tenant URLs, tokens, service keys, private keys, or production user IDs.
- Confirm the tester can access the GitHub prerelease asset.

## Step 1 - Download The Published Asset

Run from any working directory:

```powershell
$release = "sap-codex-deliverables-v0.2.0-rc1"
$repo = "MexbaliaMX/SAP_Codex_Agents"
$downloadRoot = Join-Path $env:TEMP ("sap-v020-rc1-manual-smoke-" + [guid]::NewGuid().ToString("N"))
New-Item -ItemType Directory -Path $downloadRoot | Out-Null
gh release download $release --repo $repo --pattern "$release.zip" --dir $downloadRoot
$zip = Join-Path $downloadRoot "$release.zip"
Get-Item -LiteralPath $zip | Select-Object FullName,Length,LastWriteTime
```

Expected result:

- The file exists.
- The file name is `sap-codex-deliverables-v0.2.0-rc1.zip`.
- The file size is `1,576,400 bytes`.

## Step 2 - Verify The Downloaded Asset Hash

```powershell
Get-FileHash -LiteralPath $zip -Algorithm SHA256
```

Expected result:

```text
6BCD9E94BEDA196C149950118AE5B3C4AD794217DB68DBE69F5A4721A8AA053F
```

Fail the smoke if the hash differs.

## Step 3 - Extract Into A Disposable Install Root

```powershell
$extractRoot = Join-Path $env:TEMP ("sap-v020-rc1-manual-install-" + [guid]::NewGuid().ToString("N"))
New-Item -ItemType Directory -Path $extractRoot | Out-Null
Expand-Archive -LiteralPath $zip -DestinationPath $extractRoot -Force
Get-ChildItem -LiteralPath $extractRoot
```

Expected paths:

```text
marketplace.json
plugins\sap-codex-deliverables\.codex-plugin\plugin.json
plugins\sap-codex-deliverables\skills\sap-deliverable-templates\SKILL.md
plugins\sap-codex-deliverables\skills\sap-deliverable-templates\assets\operating-layer
```

  -ExpectedSha256 6BCD9E94BEDA196C149950118AE5B3C4AD794217DB68DBE69F5A4721A8AA053F

Expected result:

- Plugin validation passed.
- Disabled config check passed with `config example active keys: []`.
- Release archive smoke passed.

## Step 5 - Open The Plugin Install URL

Build a Codex plugin URL that points to the extracted `marketplace.json`:

```powershell
$marketplace = Join-Path $extractRoot "marketplace.json"
$encodedMarketplace = [System.Uri]::EscapeDataString($marketplace)
$pluginUrl = "codex://plugins/sap-codex-deliverables?marketplacePath=$encodedMarketplace"
$pluginUrl
Start-Process $pluginUrl
```

Expected result:

- Codex opens the plugin install or plugin detail view for `sap-codex-deliverables`.
- The plugin can be installed or loaded from the extracted marketplace.
- No MCP server, hook, tenant, credential, or production action is enabled as part of installation.

If `Start-Process` does not open Codex, copy the printed `codex://...` URL into a browser or launcher that can hand it to Codex.

## Step 6 - Confirm Plugin Load In A Fresh Codex Task

Create a new Codex task after the plugin is installed or loaded. Use a fresh task so the result is not contaminated by this release engineering thread.

Use this prompt:

```text
Use sap-deliverable-templates to draft a brief SAP S/4HANA Mexico go-live readiness advisory for an anonymized internal demo release. Use the evidence-bound audit style. Separate confirmed facts, assumptions, validation gaps, risks, owners, and next actions. Do not claim live tenant validation, fiscal/legal approval, security approval, or production readiness.
```

Expected task behavior:

- The task recognizes or uses `sap-deliverable-templates`.
- The output uses plugin-local deliverable structures or operating-layer guidance.
- The answer is advisory and evidence-bound.
- Mexico fiscal topics such as CFDI, complementos de pago, Carta Porte, SAT evidence, approval evidence, and auditability are treated as validation items where relevant.
- The answer does not claim tenant facts, legal/tax approval, security approval, licensing approval, go-live approval, or production readiness.

## Step 7 - Authorization Review Pack Smoke

In the same fresh task or a second fresh task, use this prompt:

```text
Use the SAP deliverable template assets from the installed sap-codex-deliverables plugin to outline an authorization evidence intake and review pack for a Procure-to-Pay Fiori access review. Keep it advisory, list required sanitized evidence, approval gates, risks, owners, and next actions. Do not invent SAP app/catalog availability or tenant configuration.
```

Expected task behavior:

- The output requests sanitized evidence before conclusions.
- The output includes a traceability chain such as process role, business task, Fiori app or transaction, catalog/menu, service/CDS/backend object, authorization object or DCL, and user test.
- The output separates confirmed facts, assumptions, gaps, risks, recommendations, owners, and approval gates.
- The output does not approve role changes, SoD exceptions, emergency access, production transports, or tenant-connected automation.

## Step 8 - PASS Criteria

Mark the manual install/load smoke as PASS only if all of the following are true:

- Published GitHub prerelease asset downloads successfully.
- Downloaded asset SHA256 matches the expected value.
- Extracted archive contains `marketplace.json`, plugin manifest, plugin skill, templates, samples, and operating-layer assets.
- Codex opens the plugin install/load flow from the extracted marketplace.
- A fresh Codex task can use the installed plugin skill or plugin assets.
- Smoke output is evidence-bound and advisory.
- Smoke output avoids live SAP tenant, legal/tax, security, licensing, go-live, and production-readiness claims.
- No MCP servers, hooks, tenant credentials, or production actions are enabled.

## FAIL Conditions

Fail the smoke if any of these occur:

- The downloaded asset hash differs from the expected SHA256.
- The plugin install URL cannot load the extracted marketplace.
- Codex cannot install or load `sap-codex-deliverables`.
- A fresh Codex task cannot see or use the plugin skill/assets.
- Output invents SAP tenant facts, app/catalog availability, licensing claims, fiscal/legal approval, security approval, or production readiness.
- Output asks for or exposes credentials, tenant secrets, personal data, production user IDs, service keys, private keys, or tokens.
- Installation enables MCP servers, hooks, tenant access, or production automation without separate explicit approval.
